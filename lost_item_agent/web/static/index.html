PROJECT FORMULATION

Methodology

The simulation demonstrates classical search and agent problem formulation.

PEAS

Performance
Reduce movement and inspection effort; record search work and runtime.
Environment
A weighted campus graph or an obstacle grid; blocked corridors can be simulated.
Actuators
Move through connected locations and inspect candidate rooms.
Sensors
Position, blocked passages, and item location are supplied simulation inputs—not real sensors.

Problem formulation

State
Current location and remaining candidate locations.
Actions
Move to a connected campus node or adjacent grid cell.
Transition
Follow an unblocked edge or enter a walkable neighboring cell.
Goal
Reach the designated location and inspect it successfully.
Cost
Sum of movement costs; room search effort is used in candidate ranking.

Search algorithms

BFS
FIFO frontier; minimizes edge count on unweighted graphs, not weighted cost.
Greedy
Prioritizes h(n); does not guarantee a lowest-cost path.
A*
Prioritizes g(n) + h(n); cost-optimal when the heuristic is admissible.
Heuristics
Euclidean distance for campus coordinates, Manhattan distance for four-direction grids, or zero.

Candidate search

Candidates are ranked using movement cost, room-search effort, and user-provided belief. The recommended multi-room tour uses a greedy nearest-neighbor approximation; it is not a guaranteed optimal TSP tour.

The selected actual item location is simulation truth, not a learned probability or sensor reading.

Local academic simulation · Search results are generated by the Python algorithms.
