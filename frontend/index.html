PLAIN-LANGUAGE GUIDE

How it works

Here is what the simulation does—and what it does not do.

What does the agent do?

It takes your current location and a list of places you think you visited, then finds paths through a sample campus layout. When you run a recovery demonstration, it checks the places one by one and replans after each unsuccessful check.

It cannot track a real person or detect a real item. The map and recovery result are simulated.

How are places suggested?

Item types start with a short list of plausible places. You can change the list. If you have a hunch, you may optionally say some places are more likely; the program uses your input, it does not learn from data.

The suggested visit order is a practical shortcut, not a promise of the single shortest tour.

How does it find a route?

Balanced route: considers both distance already travelled and distance left. Fewest steps: prefers fewer connections. Head toward the destination: follows the closest-looking direction, but can take a longer way around obstacles.

For the project, these are A*, Breadth-First Search (BFS), and Greedy Best-First Search.

What do the results mean?

Places checked: locations the route finder examined. Route length: number of moves. Travel cost: movement effort on the sample map. Time: computer time for the search, not walking time.

These measures show different things; a faster run does not automatically mean a shorter route.

Technical project terms (for coursework review)

PEAS

Performance: reduce movement and inspection effort and record search work. Environment: a weighted campus graph or obstacle grid. Actuators: move through connections and inspect rooms. Sensors: all positions and simulation truth are user-provided inputs; no real sensors are integrated.

Search formulation

State: current location and remaining candidates. Actions: move along an open connection. Goal: reach and inspect the designated location. Cost: sum of movement weights.

Search properties

BFS uses a FIFO queue; Greedy orders by h(n); A* orders by g(n) + h(n). A* is cost-optimal when its heuristic is admissible. Manhattan distance suits four-direction unit-cost grids; Euclidean distance is used on the campus graph.

Candidate tour

Candidate priority is (movement cost + room inspection effort) × (1 − user belief). Tour planning uses a greedy nearest-neighbor approximation, not an optimal TSP solution.
